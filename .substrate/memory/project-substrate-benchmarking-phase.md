Substrate (the runtime) is built and conformance-gated. The next phase the Architect wants is a **research phase: benchmark the topologies (the applications) on real, public, known LLM benchmark datasets**, A/B against a single-model baseline, step by step — and reshape a topology where it doesn't fit a benchmark's task shape. Goal: launch with applications benchmarked for real, not just replay+conformance.

**Hard correction from the Architect (do not repeat):** a topology is a different stochastic/mathematical object than one model — independent exterior stochastic sources interacting. Framing them as "agents that beat one strong model on accuracy" is a category error. Do NOT map dynamics topologies onto QA accuracy sets as if the question were "does it beat one model." And never launder a vague claim ("recent studies show debate doesn't help") as fact.

**The split (from reading the topology code):**
- *Answer-producing → a public benchmark fits, A/B is real:* `coding_flow` (best-of-N + build gate → SWE-bench Verified / LiveCodeBench; closest to ready, already sandboxes a gate), `tool_loop` (→ tau-bench / BFCL), and code-shaped `pair_coding` / `code_review` (code_review needs a defect dataset; no clean public review set).
- *Dynamics-instrumenting → measurement is intrinsic, no benchmark-answer:* `debate` (positional asymmetry; output is both transcripts, no judge), `prisoners_dilemma` (payoff; observable = typed `Decision`), `intel_asymmetry` (information; observable = `JointCall` calibration vs a known-truth scenario), `natural_conversation` vs `_bare` (the ablation delta IS the measurement), `adversarial_pair` (artifact-improves-under-finder), `recursive_decomposition` (purely structural — nothing to score on a QA set).

Current benchmarking in-repo = N-PERF-1 (append throughput) + 17 conformance checks + observation contracts. These are correctness/throughput, NOT value benchmarks. The whitepaper (round 2) states the central claim as a bet and specifies one unrun planted-trap experiment for the error-correction method.
