# Substrate locked vocabulary v0.4 — rationale

Locked 2026-11-05, sprint K340, agent-resolved. Successor to v0.3 (2026-08-27), which stays on disk under `signals/0.3.json`.

## What v0.4 changes

One rule, `SEQUENCE_RULE_PROPOSED`, placed after PAUSE/RESUME RE-ENTRY in `state_transitions.rules`:

**AT-REST APPEND.** While a run is paused (its last frame is `substrate.TerminationMatched` with decision `pause-await-input`), an application event may be appended without resuming it. The append takes the record's exclusive lock, writes the event with `producer` null, and then writes the pause again: a `substrate.TerminationMatched` with the same payload, `producer` null. No Trigger is evaluated and no Producer runs. The record ends paused, and the run is re-entered only by a resume. Never after `substrate.RunFinalised`. A reserved `substrate.*` kind is refused.

The call is `api.append_at_rest(record_root, event)` in `src/substrate/kernel/runtime.py`.

No new tag. No payload field. The twelve reserved lifecycle kinds are unchanged. A run writes the same frames it wrote under v0.3; the only frame that differs is `RunStarted.config.vocab_version`, which now says `0.4`.

## Why

A session is paused on disk between turns, and an edit the person makes in the editor view while the session waits for input has to reach its record (substrate-ui research r8, "Every edit made in a view goes on the record", and r11 shared item 0(d)). `Runtime.inject_event` appends only to a live run. `Runtime.resume` appends to a paused one, but its event resumes the run, and for a session the resume event is the `UserMessage` that starts a turn.

## Why the pause is written again

Three readers take the record's last frame as the run's state: the session registry's status scan (`_scan_record_status`, last frame a pause means `parked`), the graph projection (`projections/graph.py`, a pause is the run's state only while nothing follows it) and `Runtime.resume`, which needs a resumable record. An event left as the last frame would make each read a parked session as interrupted. Writing the pause again keeps all three right without changing any of them, and the record says what is true: the run was paused before the event and is paused after it.

Two other shapes were weighed. A new reserved kind (`substrate.AppendedAtRest`) would grow the twelve lifecycle kinds and still need every tail reader taught to skip it. Teaching the readers to skip trailing externally-written frames cannot tell an at-rest append from a resume event whose run died before its first Trigger, which today reads as interrupted, and that reading would change.

## Why not after RunFinalised

RUN-BOUNDARY says `substrate.RunFinalised` is terminal and no event follows it. Writing it again after an event would make it appear twice. An ended session therefore refuses an at-rest append (`RecordNotAtRestError`).

## Migration

Records written under v0.3 are valid under v0.4: none holds an at-rest append. The 18 bundled CI records under `src/substrate/topologies/*/records/ci_mode.record` have their `RunStarted` frame rewritten with `vocab_version` `0.4` and a new CRC; no other byte of them changes.
