# process/sprints — index

*Current as of 2026-11-20. The project's task cards. Each is `sprint-NNN-subject.md`, numbered in order and never reused; the kernel cards run sprint-000 through sprint-357 as of this date. A card's `status` field changes as the work moves; the rest of a closed card does not. This folder holds the cards; the roadmap that groups a run of them into a piece of work lives in the matching `process/planning/<piece>/`, and each close is recorded in `process/BLACKBOARD.md`.*

A card's frontmatter carries one `status` from this set, with the counts in use on 2026-11-20:

| Status | Meaning | Count |
|---|---|---|
| `closed` | the card's work landed and its contract passed | 204 (+4 `closed-2026-08-31`) |
| `pending` | written, not yet dispatched | 22 |
| `open` | dispatched, not yet closed | 11 |
| `withdrawn` | the work was taken back | 6 |
| `superseded` | a later card replaces it | 2 |
| `split-into-…` | the card split into lettered sub-cards | 3 |
| `held`, `done`, and one `halted` row | one-off states named on the card | 3 |

A few early cards carry names other than `sprint-NNN` (for example `GO-PUBLIC-SWEEP.md`); they predate the numbering and keep their names. The next card number follows the last one on the BLACKBOARD.
